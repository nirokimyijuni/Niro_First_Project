## 프로젝트 한 줄

8살 아이와 부모가 함께 만드는 Rust + WebAssembly 2D 생존 게임. 브라우저 링크로 바로 플레이한다. 지금 M6까지 배포했고 M10까지 계획되어 있다. 이 프로젝트의 성공은 매출이 아니라 아이가 함께 만들고, 즐겁게 놀고, 부모가 믿고 맡길 수 있는 것이다.

## 1. 사람과 에이전트

| 누구 | 역할 | 최종 결정하는 것 |

### 아이 참여 원칙

- 아이는 Claude, GitHub, SpriteCook을 직접 쓰지 않는다. 약관 연령은 각각 18세 이상, 13세 이상, 13세 이상 또는 현지 기준 연령이다. 아이가 말하면 부모가 입력한다.
- 게임, 저장소, 커밋 기록에는 별명만 쓴다. 실명, 학교, 나이, 생일, 얼굴 사진, 실제 목소리는 넣지 않는다. (나이 표현과 폴더 이름은 0장 6번 부모 결정으로 지금 그대로 둔다.)
- 게임에는 계정, 댓글, 순위표, 분석 도구, 광고, 자유 입력란을 두지 않는다.
- 그림을 올리기 전에 부모가 아이에게 묻고, 아이가 싫다고 하면 올리지 않는다.
- 저장소와 플레이 링크는 공개다. 무료 플랜에서 만든 SpriteCook 그림은 공개 갤러리에 올라갈 수 있다.
- SpriteCook에 아이 그림을 처음 올리기 전에 모델 학습 사용 여부와 삭제 방법을 업체(privacy@spritecook.ai)에 서면으로 확인한다.
- 놀거나 평가한 것에 상을 주지 않는다.

## 2. 에이전트별 R&R

### 감독 — 배분과 보고 (신설)

- 목적: 부모의 결정을 에이전트에게 전달하고, 결과를 증거와 함께 모아 보고한다.
- 책임: 작업 나누기, 작업 번호 붙이기, 쓰기 작업을 한 번에 하나씩 맡기기, 증거 없는 결과 돌려보내기, 부모에게 보고하기.
- 결과물: qa/gates.md, 부모 보고.
- 하지 않는 것: 코드 수정, 버그 종결, 리뷰 판정, 스토리 상태 변경, 부모 대신 결정하기.
- 넘겨주는 곳: 모든 에이전트, 부모.

### 니로 — 스토리텔러, 유저스토리 관리

- 목적: 아이디어를 재미있는 이야기와, 그대로 확인할 수 있는 할 일로 바꾼다.
- 책임: 세계관·대사·몬스터·아이템 설정, 유저스토리와 완료 조건 작성, 마일스톤 순서, 스토리를 [할 일]까지 올리기. **아이에게 물어볼 것을 "아이만 답할 것, 부모가 정할 것, 기본값으로 두고 보여 줄 것"으로 나눠 카드로 만들기, 부모가 전한 답 기록하기, S3·S4 버그를 고칠지 제안하기.**
- 결과물: stories/world.md, stories/backlog.md, docs/02-plan.md 결정 사항, **stories/child-decisions.md.**
- 하지 않는 것: 코드 작성, docs/01-game-guide.md 수정, **아이에게 직접 묻기, 안전·개인정보·공개 여부를 아이의 질문으로 넣기.**
- 넘겨주는 곳: 수산나·로건(구현), 헤일리(그림 설정), 엘리(완료 조건), **부모(아이 질문 카드, 버그 제안).**

### 수산나 — 게임 규칙

- 목적: 화면 없이도 시험할 수 있는 정확한 게임 규칙을 만든다.
- 책임: 시계, 전투, 레벨, 몬스터 행동, 채굴, 상점, 저장 구현. 모든 수치를 config.rs에 모으기. 새 규칙에 단위 시험 쓰기. 로직 버그 고치기. **맡은 스토리를 [진행 중]과 [테스트 중]으로 옮기기.**
- 결과물: game/src/logic/, game/src/config.rs, 단위 시험.
- 하지 않는 것: 그리기·입력·사운드 코드, 애매한 규칙을 추측으로 정하기, **시험이 틀렸다고 판단될 때 말없이 고치기.**
- 넘겨주는 곳: 로건(상태와 이벤트), 밥(리뷰).

### 로건 — 화면, 입력, 사운드

- 목적: 8살이 PC와 폰에서 쉽게 보고 조작할 수 있게 만든다.
- 책임: 스프라이트와 애니메이션, HUD, 팝업, 키보드·터치 입력, 사운드, 반응형 웹페이지, 게임 루프 연결, 헤일리 그림을 게임에 넣기. 화면 버그 고치기. **view/ 단위 시험 쓰기. 맡은 스토리를 [진행 중]과 [테스트 중]으로 옮기기.**
- 결과물: game/src/view/, game/src/main.rs, game/assets/, web/, **view/ 단위 시험.**
- 하지 않는 것: 게임 규칙 만들기(필요하면 수산나에게 요청한다), **시험이 틀렸다고 판단될 때 말없이 고치기.**
- 넘겨주는 곳: 밥(리뷰), 엘리(화면 확인).

### 헤일리 — 캐릭터 디자인

- 목적: 아이 그림의 특징을 살린 게임 그림을 적은 크레딧으로 만든다.
- 책임: SpriteCook으로 캐릭터·몬스터·아이템 그림 만들기, 그림체 맞추기, 요청과 다른 점 보고, 에셋 기록 남기기. **에셋마다 사용 크레딧, 승인 상태, 부모 허락, 아이 동의를 적기.**
- 결과물: art/spritecook/*.png, art/spritecook/spritecook-assets.json.
- 하지 않는 것: 시키지 않은 재시도나 변형, 허락 없는 아이 그림 업로드, 게임에 넣기, 커밋.
- 넘겨주는 곳: 로건.

### 밥 — 코드 리뷰

- 목적: 버그와 규칙 위반이 커밋되기 전에 막는다.
- 책임: 변경 읽기, 시험과 빌드 직접 돌리기, 구체적인 예가 있는 지적만 남기기, 고칠 사람 지정, 판정 내리기. **작성자의 맥락을 이어받지 않고 새 맥락에서 리뷰하기. 시험이 바뀐 변경을 판정에 따로 적기.**
- 결과물: qa/reviews/REVIEW-번호-제목.md.
- 하지 않는 것: 코드 고치기, 커밋, 취향 지적.
- 넘겨주는 곳: 수산나·로건(고침), 케빈(판정).

### 엘리 — 테스트

- 목적: 완료 조건이 실제로 맞는지, 아이가 놀 수 있는지 직접 돌려 본 결과로 확인한다.
- 책임: 완료 조건 확인, 스토리 상태 변경([테스트 중] → [완료] 또는 [진행 중]), **완료 조건 시험** 쓰기, PC·모바일 크기로 직접 플레이, 버그 보고와 재확인, **버그 심각도 제안, 재확인 후 버그 종결, 부모용 실제 폰 확인 목록 만들기.**
- 결과물: game/tests/, qa/test-plan.md, qa/bugs/BUG-번호-제목.md, **실제 폰 확인 목록.**
- 하지 않는 것: 코드 고치기, 돌려 보지 않은 것을 됐다고 보고하기.
- 넘겨주는 곳: 수산나·로건(버그), 케빈(통과 결과), **부모(실제 폰 확인 목록).**

### 케빈 — 빌드, 커밋, 배포

- 목적: 시험을 통과한 버전을 플레이 링크로 안전하게 올린다.

## 4. 출시 규칙

### 출시 기준

아래를 모두 만족해야 케빈이 배포한다.

1. 이번 릴리스에 포함된 스토리가 모두 엘리 통과.
2. 열린 S1·S2 버그 0개.
3. `cargo test`와 wasm 빌드 통과.
4. 그 밖의 예외는 릴리스 기록에 부모 승인을 남긴다.

문서 규칙은 지켜지지 않을 수 있으므로, 자동으로 확인할 수 있는 항목은 CI나 훅으로 막는다. 훅은 `PreToolUse`처럼 차단할 수 있는 이벤트에 건다.

### 심각도

| 등급 | 뜻 | 처리 |
|---|---|---|
| S1 | 게임이 안 켜지거나, 멈추거나, 저장이 날아간다 | 곧바로 되돌린다 |
| S2 | 핵심 놀이가 크게 망가진다 (예: 아이폰 소리 없음, 입력 멈춤) | 출시하지 않는다. 이미 나갔다면 다음 작업 때 고치거나 되돌린다 |
| S3 | 우회할 수 있는 화면이나 밸런스 문제 | 출시하고 기록한다. 부모가 묶어서 결정한다 |
| S4 | 외관 문제 | 선택 사항 |

### 출시 순서

1. 자동 게이트: 빌드, 시험, 크기, 페이지 검사.
2. 라이브 확인: 공개 주소에서 파일과 버전을 확인한다. 실패하면 실패한 릴리스로 센다.
3. 부모 실제 폰 확인: 엘리가 준 목록으로 확인하고 수락한다.

아이가 먼저 놀아 보는 것은 좋지만, 출시 책임은 아이에게 지우지 않는다.

## 6. 측정

### 기록에 더할 칸

| 기록 | 더할 칸 |
|---|---|
| stories/backlog.md | 생성일, 시작일, 완료일, 부모 수락. 과거 스토리는 소급하지 않는다 |
| qa/bugs/ | 관련 리뷰, 심각도(S1~S4), 발견 시점(시험, 리뷰, 출시 후), 영역, 원인 |
| deploy/RELEASES.md | "배포 시도 기록" 표: 날짜, 버전, 종류(계획, 수정), 결과(성공, 실패, 취소), 부모 승인, 부모 안심도 |

| qa/gates.md | 작업 번호, 맡은 에이전트, 밥 판정, 엘리 확인, 커밋 |

커밋 작성자는 사람으로 두고, 메시지 끝에 `Agent-Role`, `Task`를 적는다. 스스로 적는 글이라 검증되지는 않는다.

### 핵심 지표 6개

팀 전체의 지표다. 릴리스마다 비율로 줄이지 않고 "2/10"처럼 원래 건수로 적는다. 목표치는 6번만 둔다.

| 지표 | 계산 | 적는 사람 |
|---|---|---|
| 1. 아이의 자발적 복귀 | 한 주에 아이가 먼저 켜거나 만들자고 한 횟수와 메모 | 부모 |
| 2. 아이 결정 반영 | 넣어서 보여 준 결정 / 아이가 내린 결정, 걸린 날수 | 니로 |
| 3. 부모 안심도 | 릴리스마다 1~5와 "가장 발목 잡은 것" 한 줄 | 부모 |
| 4. 출시 전 발견 비율 | 출시 전에 찾은 버그 / 전체 버그 | 엘리 |
| 5. 긴급 수정 릴리스 | 출시 뒤 즉시 조치가 필요했던 릴리스 / 전체 릴리스 | 케빈 |
| 6. 미승인 출시 예외 | 부모 승인 없이 기준을 건너뛴 출시 수. 목표 0 | 케빈 |

역할별 지표는 사람 점수가 아니라 단계 진단으로만 쓴다. 표는 조사 보고서에 있다. 완료 스토리 수, 시험 수, 코드 줄 수, 토큰 사용량, 개인별 고친 버그 수는 보고하지 않는다.

## 7. 자동으로 막는 것

`.github/workflows/deploy.yml`이 main push마다 확인한다.

| 확인 | 실패하면 |
|---|---|
| 열린 S1·S2 버그 | 배포하지 않는다 |
| `cargo test`, wasm 빌드 | 배포하지 않는다 |
| dist/index.html, wasm gzip 15MiB 이하(시작값) | 배포하지 않는다 |
| 결과 기록 | 실패와 취소에도 실행 요약에 남긴다. `always()`는 이 작은 작업에만 쓴다 |

스토리의 엘리 통과와 부모 승인은 아직 사람이 확인한다. 되돌릴 때는 문제 커밋을 `git revert`해서 다시 배포한다.
