# REVIEW-004 M3 마무리

- 리뷰한 사람: 밥 (코드 리뷰어)
- 날짜: 2026-11-06
- 대상: 아직 커밋하지 않은 코드 변경 전부 (마지막 커밋 3daa351 다음)
  - 로건: BUG-005, 주인공 픽셀 그림 교체(D23), 오른쪽 절반 점프(D25), 메뉴 탭을 `fingers()` 길로 변경, `web/index.html`, 대시보드 그림 경로
  - 수산나: BUG-006 `logic/player.rs` `move_one_step`, `PLAYER_EDGE_SLIDE_SPEED`
- `art/`, `stories/`, `docs/`는 훑어만 봤어요. 루트의 스크린샷은 대상이 아니에요.

## 이 변경이 하는 일

폰 조작을 마무리해요. 왼쪽 끝에 엄지를 대기만 해도 걷던 문제(BUG-005)를 고치고, 오른쪽 절반 어디를 눌러도 점프가 되고(D25), 터치는 메뉴에서도 `fingers()` 한 길로만 들어와요. 웹페이지는 캔버스 크기를 다시 맞추고, 안드로이드에서 전체화면과 가로 고정을 시도해요. 주인공 그림은 픽셀 그림으로 바뀌고, 상자 끝에서 몸 가운데가 밖으로 나가면 미끄러져 떨어져요(BUG-006).

## 잘한 점

- **터치 길을 하나로 합친 것.** 마우스 흉내를 끄고 메뉴도 `idle()`의 "새 손가락"만 탭으로 쳐서, 폰을 쥔 엄지가 움직여도 탭 자리가 덮어써지지 않아요. `menu_tap_is_only_a_new_finger` 테스트가 엄지, 두 손가락, 짧은 톡까지 지켜 줘요.
- **BUG-006 고침이 작고 테스트가 튼튼해요.** 코드는 몇 줄이고, 테스트는 상자 3개 전부, 양쪽, 끝 값, 떨림, 큰 dt까지 봐요. `PLAYER_EDGE_SLIDE_SPEED`가 왜 걷기보다 느려야 하는지 설명한 주석도 좋고, 그 조건이 깨지면 `pushing_back_toward_box_while_slipping_never_gets_stuck`가 실패해요.
- **전체화면 코드가 실패에 강해요.** 함수가 없으면 돌아가고, 바로 나는 오류는 `try`가, 나중의 거절은 `.catch`가 받아요.

## 고치면 좋은 것

### 2. 미끄러지는 동안 누른 점프가 사라져요. 이렇게 정한 건가요? (수산나)

- **무엇이 문제인지**: 미끄러지는 동안 `on_ground`가 false라서 `update`의 점프 조건을 못 넘어요. 그리고 이 동작을 지키는 테스트가 없어요.
- **어떤 경우에 틀리는지**: 상자 왼쪽 끝 5픽셀 밖에 내려앉아 미끄러지는 중에 점프를 누르면 `vel.y`가 0 그대로이고, 8프레임 뒤에 그냥 떨어져요. 미끄러지는 시간은 길어야 약 0.2초(23.5픽셀 ÷ 초당 120픽셀)예요. 또 걸어서 나갈 때 점프할 수 있는 마지막 자리가 이전보다 약 24픽셀 앞당겨졌어요. 가운데 상자에서 마지막으로 서 있던 몸 가운데는 621.3, 상자 끝은 624예요. 상자 끝까지 달려서 뛰려던 아이는 "눌렀는데 안 뛰어"라고 느낄 수 있어요.
- **가장 작은 고침**: 이대로가 맞다면 `pushing_back_toward_box_while_slipping_never_gets_stuck`(`game/tests/m1_movement.rs:360`)에 "점프를 눌러도 위로 안 뛰고 `Motion::Jump`다"를 확인하는 줄을 더해요. 점프가 되는 쪽이 좋은지는 아이가 해 보고 정할 거리예요.

### 5. `web/index.html:69` 주석은 "첫 터치 때"인데, 코드는 손가락을 뗄 때마다 시도해요 (로건)

안드로이드 뒤로 가기로 전체화면을 나가도, 다음에 손가락을 떼면 다시 전체화면이 돼요. 게임 중이면 놀다가 화면이 바뀌고요. 다른 앱에 다녀왔을 때는 이쪽이 편해서 일부러 그런 것일 수 있어요. 일부러라면 주석을 "전체화면이 아니면 손가락을 뗄 때마다"로 고쳐요. 한 번만 할 거라면 리스너에 `{ once: true }`를 줘요.

### 6. 양옆 띠가 없는 화면에서는 왼쪽 끝 21픽셀 안에서 왼쪽으로 못 걸어요 (로건)

## 이번 변경과 무관

### 8. 남은 시간 조각이 아주 작으면 상자 위에서 한 프레임 공중으로 쳐져요 (수산나)

이번 변경을 막는 이유는 아니에요. 마지막 커밋 3daa351에서도 숫자가 똑같이 나와요.

- **무엇이 문제인지**: `Player::update`(`player.rs:96-100`)는 1/120초씩 자르고 남은 조각을 마지막 걸음으로 돌려요. 조각이 아주 작으면 아래로 움직인 거리가 소수 정밀도보다 작아서 `pos.y`가 안 바뀌어요. 그러면 상자와 안 겹친 걸로 나와 `on_ground`가 false로 끝나요. 땅은 `>=`로 재서 괜찮고, 상자 위에서만 생겨요.
- **어떤 경우에 틀리는지**: 상자 위에서 200번 점프를 눌러 봤어요.

  | 프레임 시간 | 점프 성공 | 점프 모습으로 보인 프레임 |
  |---|---|---|
  | 1/60초 그대로 | 200/200 | 0/2600 |
  | 0.0167초 | 0/200 | 2600/2600 |
  | 0.0166, 0.0167, 0.0167 번갈아 | 67/200 | 1733/2600 |

  다만 **웹에서는 드물어요.** 번들의 시간이 `Date.now()`(1밀리초 단위)라서 0.0167 같은 값이 안 나와요. 1~250ms를 하나씩 재 보니 50, 75, 100, 125ms 프레임에서만 생겼어요. 시계가 더 촘촘한 PC 실행(`cargo run`)에서는 더 자주 날 수 있는데, 거기서는 재 보지 않았어요.
- **가장 작은 고침**: 프레임을 같은 크기로 나눠요. 임시 복사본에서 시험하니 위 표가 모두 200/200, 0/2600이 되고, `m1`·`m2`·`m3` 테스트도 모두 통과했어요.
  ```rust
  let dt = dt.max(0.0);
  let steps = (dt / PHYSICS_STEP_SECONDS).ceil();
  let step = dt / steps.max(1.0);
  for _ in 0..steps as u32 {
      self.move_one_step(step, world);
  }
  ```
