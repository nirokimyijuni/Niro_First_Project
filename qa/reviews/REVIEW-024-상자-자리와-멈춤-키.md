- 리뷰어: 밥 / 날짜: 2026-11-15 / 대상: 커밋 전 작업 트리 (fb4d8db 다음), REVIEW-023(08:28) 뒤에 바뀐 것
- 기준: docs/02-plan.md D36·D91·D99, stories/backlog.md 임시-11·임시-22·임시-70, US-050 니로 메모, BUG-033, REVIEW-023

## 이 변경이 하는 일
동굴 입구와 집 문 둘레에 상자를 더 넓게 비워요 (D99). 동굴은 양옆 196픽셀, 집 문은 104픽셀이에요. 그래서 화산에는 상자가 늘 0개가 되고(부모님 승인), 집에는 시민과 문 사이에 작은 상자 자리가 하나 남아요. 멈춤 창은 ↑/↓로 칸을 고르고 Enter·Space로 정하며 고른 칸이 주황색이에요. 가방 아래 키 안내는 어두운 띠 위의 큰 글씨가 됐어요 (BUG-033).

## 잘한 점
- **상자 비우기가 아주 작아요.** `no_box_zones`에 동굴·문 두 구간만 따로 넓게 넣었고, 상자를 빼는 규칙(`keep_boxes_out_of_zones`의 틈 규칙)과 "빈 장소에 하나 남기기"는 그대로 써요. 새 시험 `no_box_around_cave_entrance_and_house_door_on_any_seed`가 시드 여러 개로 거리, 집에 상자 1개 이상, 틈 규칙을 한 번에 봐요. 그리고 `const { assert!(..) }`로 config 값이 "몸 2개 + 들어가기 범위"보다 작아지면 컴파일부터 실패해요.
- **멈춤 키 판단을 `pause_choose` 하나로 뺐어요.** Esc는 늘 이어서 하기, ↑↓ 같이 누르면 그대로, ↓+Enter 같은 프레임 같은 경계까지 단위 시험이 있어요.

## 1. 상자 비우기 (수산나) — 계산으로 다시 확인
- 화산(960~1920), 상자 놓는 곳 1176~1824: 동굴 구간 816~1304, '화산 뒤' 숨는 곳 1236~1364, 시민 1340~1660, 구멍 1556~1844. **빈 곳이 하나도 없어서 늘 0개**예요. config·world.rs 주석("늘 0개")이 맞아요. 예전(양옆 64)에는 1176~1236(60픽셀)에 작은 상자가 들어갈 수 있었어요.
- 집(2880~3840), 상자 놓는 곳 3096~3744: 나무 ~3128, 시민 3040~3360, 문 3417~3693, '집 뒤' 3636~3764. **3360~3417(57픽셀)만 남아 작은 상자(48) 하나가 들어가요.** 빈 자리 찾기가 4픽셀씩이라 3360에 딱 맞춰 찾아요. config 주석 "이보다 넓히면 집에 상자 자리가 없어진다"도 맞아요 (여유 9픽셀). 넓히면 새 시험이 "집에 상자가 없다"로 깨지니 몰래 0개가 되지는 않아요.
- 부서진 상자는 처음 자리로 돌아오니(D87) 둘레 규칙이 그대로 지켜져요.

### 바뀐 시험 (따로 적음)
- `m6_map every_place_has_boxes_and_never_more_than_ten`: 화산만 0개 허용. D99와 US-050 니로 메모 그대로예요. 다른 장소는 여전히 1개 이상을 봐요. **약해진 것은 부모님이 정한 예외 하나뿐**이에요.
- `m6_miss_weapons` BUG-019 시험 2개 (진짜 맵 상자 → 직접 놓은 상자):
  - **진짜 맵에는 이제 시민 왼쪽 400 안에 상자가 없다**는 근거를 계산으로 확인했어요. 시민0(1500) 왼쪽 1100~1340은 위 화산 계산대로 전부 비우는 구간이고, 시민1(3200) 왼쪽 2800~3040은 산의 상자 놓는 곳(~2784) 밖이고 집 쪽은 나무·제작대·시민 구간이에요. 그래서 예전 시험은 "상자 뒤 시민 0곳"으로 아무것도 못 보게 됐고, 직접 놓는 방식이 맞아요.
  - **건너뛰는 자리는 버그를 숨기지 않아요.** 건너뛰는 것은 시민0 앞 `extra` 0·48·96(상자가 '화산 뒤' 숨는 곳 ±64에 걸림)뿐이에요. 이 자리는 D99 전에도 숨는 곳 둘레(`NO_BOX_MARGIN`, 임시-5) 때문에 진짜 맵에 상자가 놓인 적이 없어요. 겹침 판단도 world.rs `is_in_a_zone`과 같은 "끝이 닿으면 겹침 아님"이에요. 화산 시민 앞 큰 상자에서 시민 위로 떨어지는 일은 진짜 게임에서는 생길 수 없어요. 다만 그 이유는 D99가 아니라 숨는 곳 둘레라서, 나중에 숨는 곳 둘레를 줄이면 다시 볼 자리예요 (아래 작은 것 5번).
  - **더 세진 곳도 있어요.** 시민0 앞 extra 144·192 상자(1084~1196)는 이제 진짜 맵이라면 동굴 구간이라 안 놓이는 자리인데도 시험해요. 시민1은 시민 둘레 바로 끝(extra 0)부터 큰·작은 상자를 다 봐요.
  - 시드 수가 200→10, 40→4로 줄었지만, 상자를 직접 놓으니 시드는 상자 자리를 바꾸지 않아요. 실제로 본 곳: 두 번째 시험 **180/240 성공** (기준 "절반 넘게", 예전과 같음), 첫 번째 시험은 실패 없이 통과 (기준 `checked > 100` 그대로).

## 2. 멈춤 창 키보드 (로건)
- **새로 누를 때만**: `MenuInput.up/down/confirm`은 모두 `is_key_pressed`예요. 창을 열 때 누르고 있던 ↓로 칸이 옮겨지지 않아요. 창을 열 때마다 `pause_pick = Resume` (main.rs 370줄) — 임시-70 "처음엔 이어서 하기"와 같아요.
- **Esc는 이어서 하기**: `pause_choose` 첫 줄. 처음으로를 골라 둔 상태에서도 시험이 있어요.
- **닫은 뒤 새지 않는지**: 멈춤 창 분기는 그 프레임에 `game.update`를 부르지 않아요 (if/else if 사슬이라 한 프레임에 한 분기만). 다음 프레임에는 Enter·Space·↑가 `is_key_pressed`라 false이고, 점프(`player_input`)·들어가기(`mine_key_down`, REVIEW-022 고침)도 `is_key_pressed`라 꾹 누른 ↑는 아무 일도 안 해요. ←/→는 `walk_lock`이 막아요. "처음으로"로 나가는 프레임에는 장면이 바뀌어 새 장면을 업데이트하지 않아요. **새는 길을 찾지 못했어요.**
- 이 "다음 프레임" 부분은 macroquad 키 상태라 단위 시험이 없고, 엘리 브라우저 확인 몫이에요 (backlog 2052줄 완료 조건).
- 고른 칸 테두리가 창 안, 두 버튼 사이에 닿지 않는지도 시험이 있어요.
