### 테스트할 때 주의 (M2)
- 이 브라우저 패널은 WebGL이 느려 초당 1~4프레임까지 떨어질 때가 있다 (빈 페이지는 56fps).
  게임은 한 프레임을 0.25초까지만 흘리므로(MAX_FRAME_SECONDS), 4프레임 아래로 떨어지면 **시계가 실제보다 느리게** 간다.
  시계 빠르기를 잴 때는 먼저 `requestAnimationFrame` 수로 프레임을 확인할 것. 진짜 폰·PC(30~60fps)에서는 문제없음.
- 패널 안에서 탭을 바꿔도 `visibilityState`가 계속 visible이라 "다른 탭에 30초" 확인은 메인 스레드를 막는 방법으로 대신했다.
- 키 입력은 JS로 canvas에 `KeyboardEvent('keydown'/'keyup', {code})`를 보내면 누르고 있기를 흉내 낼 수 있다.
- 화면 캡처가 한두 프레임 늦을 수 있다. 입력 뒤 3초쯤 기다리고 다시 찍을 것.
- 콘솔(M2 확인 때): `register_plugin is not defined`(알려진 것), `glBindTexture called with an already deleted texture ID 25!` 한 번(이번엔 17이 아니라 25).
  첫 번째 열기(창 크기 바꾸기·빨리감기·밤 플레이가 있던 세션) 중에 나옴, 정확한 순간은 못 잡음. 그 동안 게임 화면·글씨·캐릭터·코인 그림이 깨지거나 사라지는 일은 못 봄 → 버그로 올리지 않고 기록만.

### 테스트할 때 주의 (M3 마무리)
- 브라우저 패널은 다른 작업과 같이 쓴다. 앞에 놓인 탭은 다른 작업이 다른 주소로 옮길 수 있고, 패널이 숨겨지면 `requestAnimationFrame`이 멈춘다. 그래서 뒤쪽 새 탭(`tabs_create`)을 열어 `requestAnimationFrame`을 `setTimeout(16)`으로 바꾸고, 같은 콜백 안에서 게임을 그린 직후 `drawImage`로 canvas를 복사했다. 뒤쪽 탭은 페이지를 연 뒤 `resize_window`를 해야 canvas 크기가 0이 아니다.

### 테스트할 때 주의 (M3 수정)
- 패널이 hidden이면 `requestAnimationFrame`이 아예 멈출 수 있다 ("불러오는 중..."에서 안 넘어감). 콘솔에서 `requestAnimationFrame`을 `setTimeout(16)`으로 바꾸고 `animation()`을 한 번 부르면 약 50fps로 돈다. ResizeObserver는 화면 그리기 단계에서만 불려서 hidden이면 스크린샷을 찍을 때까지 늦는다.
- 캐릭터 자리는 wasm 메모리에서 찾으면 정확하다: `new Float32Array(wasm_memory.buffer)`에서 48, 64(크기) 바로 앞 4칸이 pos.x, pos.y, vel.x, vel.y. 후보가 2개면 뒤쪽이 진짜다.
- 플레이 화면 판별은 정보판 안 픽셀과 판 바로 밖 픽셀을 비교한다. 정보판 픽셀 하나만 보면 뒤로 구름이 지날 때 틀린다.
- 콘솔: `glBindTexture ... already deleted texture ID 25!` 다시 나옴. 화면 깨짐은 못 봄 → 기록만.
