## 이 변경이 하는 일

하늘·해·달·별·구름·바다 그림을 `sky.rs` 한 곳으로 옮기고 새로 그렸어요. 게임이 시작할 때 그림(텍스처, GPU에 올린 그림) 6종을 코드로 한 번 만들고(빛, 해 원판, 달, 빛기둥, 구름 3종), 매 프레임에는 그 그림을 늘이고 색을 곱해서 그리기만 해요. 하늘은 꼭짓점 색 메시(GPU가 픽셀마다 색을 섞는 판)라서 띠가 안 생기고, 구름 3겹은 먼 것일수록 작고 느리게(패럴랙스) 흘러가요.

## 잘한 점

- **그리는 곳을 `Canvas`로 나눈 것.** 게임은 GPU로, 테스트는 CPU 그림판으로 같은 함수(`draw_sky`, `draw_sea`)를 돌려요. 그래서 GPU 없이도 "그림 가장자리가 투명한가", "하늘 색이 갑자기 튀지 않는가"를 테스트로 지킬 수 있고, `export_sky_preview`로 낮·노을·밤 PNG를 뽑아 볼 수도 있어요.
- **logic과의 경계가 깔끔해요.** `sky.rs`가 logic에서 받는 값은 `sky_darkness` 하나뿐이고, `use crate::logic`이 하나도 없어요. 해가 지고 달이 뜨는 모습은 그림이고 게임 규칙이 아니라서 수치가 `config.rs`가 아니라 파일 위쪽 상수에 모인 것도 맞아요.
- 텍스처 만드는 코드가 안전해요(아래 "확인한 것").

## 확인한 것 (문제 없음)

- **텍스처 만들기**: `make_image`는 값을 `clamp(0,1)` 한 뒤 255를 곱해서 u8로 바꿔요. 넘침 없음. 인덱스 `(y*w+x)*4`는 그림 크기 안. `hash`는 `wrapping_mul`이라 넘침 패닉 없음. `value_noise`에 음수 좌표가 들어와도 `as i32 as u32`라 괜찮아요.
- **0으로 나누기**: 구름 그늘의 `(y - top_y) / (base_y - top_y)`는 덩어리 중심이 늘 `base_y`보다 위라서 분모가 0보다 커요. `above_horizon`의 `radius * 2`도 0이 아니에요.
- **알파(투명도)**: 빛·원판·달·구름 그림 모두 네 테두리가 투명해요(테스트 `generated_images_fade_out_at_edges`). 구름은 투명한 곳에도 색을 채워 두어서 늘여 그릴 때 거뭇한 테두리가 안 생겨요. 원판도 바깥 색이 가장자리 색과 같아요.
- **경계값**: 한낮 d=0 → 달 없음, 노을빛 0. 한밤 d=1 → 해 없음. d=0.85 이상이면 해 몸통·가운데 빛이 모두 수평선 아래(바다에 가려짐). 구름은 `rem_euclid`라 시간이 아무리 커져도 화면 왼쪽 밖에서 들어와요.
- **Wasm**: 스레드·`Instant` 없음. 파일 쓰기(`export_png`, `std::env`)는 `#[cfg(test)]` 안에만 있어요.
- 남은 `#[allow(dead_code)]` 없음(이번 변경 안). 아이에게 보이는 새 문구 없음.

## 고치면 좋은 것

2. **해 그림을 아이 그림으로 바꾸면 색이 바뀌고 가운데가 하얗게 덮여요** (로건, `sky.rs` `draw_sun` 652~653줄)
   - 무엇이 문제: 파일 맨 위 설명은 "텍스처만 바꿔 끼우면 그리는 함수는 그대로"라고 하는데, 해는 그렇지 않아요. 원판 그림에 `SUN_EDGE_DAY`(1.0, 0.84, 0.36)를 곱하고, 그 위에 지름 1.7r의 하얀 빛(`SUN_CORE_DAY`, 진하기 0.95)을 덮어요.
   - 이렇게 틀려요: 아이가 빨간 볼에 웃는 얼굴이 있는 해를 그려서 `sun_disc`에 끼우면, 파란·초록이 빠져 색이 누렇게 변하고 얼굴 부분은 하얀 빛에 가려 잘 안 보여요. (달은 흰색을 곱해서 괜찮아요.)
   - 가장 작은 고침: `SkyArt`에 "그린 해인지" 표시 하나(예: `sun_is_drawing: bool`)를 두고, 그린 해일 땐 색을 `WHITE`로 곱하고 가운데 빛을 건너뛰어요. 지금 당장 안 바꿀 거면 맨 위 주석에 "해는 색을 곱하므로 흰색 바탕 그림을 쓰세요" 한 줄이라도.
   - 같은 이유로 구름 크기는 `CLOUD_SIZE`(256×128) 상수로 정해져서, 아이가 정사각형 구름을 그리면 옆으로 2배 늘어나요. 그릴 크기를 `texture.width()/height()`로 정하면 괜찮아져요. (구름은 작은 것)

3. **매 프레임 그리기 수를 지키는 테스트가 없어요** (로건, `sky.rs` 테스트)
   - 무엇이 문제: 모바일 비용이 이번 변경의 걱정거리인데, 숫자가 늘어도 알 수 없어요. 이미 "약 200"이라는 말과 실제(노을 때 sky.rs만 약 284)가 달라요.
   - 이렇게 틀려요: 누가 `STAR_COUNT`를 110 → 1000으로, 빛기둥 줄 간격을 4 → 1로 바꿔도 테스트는 모두 통과해요.
   - 가장 작은 고침: 테스트 안에 호출 수만 세는 `Canvas`(10줄 정도)를 만들어 d = 0, 0.6, 1에서 `draw_sky` + `draw_sea`를 돌리고 "300번 이하" 같은 한도를 하나 걸어요.

## 작은 것

4. **같은 hash 함수가 두 개** (로건) — `screens.rs`의 `hash01`과 `sky.rs`의 `hash`는 상수만 다른 같은 함수예요. 한쪽을 고쳐도 다른 쪽은 안 바뀌어요. `sky::hash`를 `pub`으로 하고 `hash01`을 지우면 돼요(모래 알갱이 자리는 바뀌어요).
5. **같은 일을 하는 두 이름: `smoothstep`과 `ramp`** (로건, `sky.rs` 250줄) — `smoothstep(a, b, x)`는 `ramp(x, a, b)`를 부르기만 해요. 같은 파일 안에서 인자 순서가 다른 두 이름이 섞여서, `smoothstep(base_y + 10.0, base_y - 6.0, y)`처럼 거꾸로 쓴 곳을 읽을 때 헷갈려요. `ramp` 하나로 맞춰요.
6. **항상 통과하는 테스트 줄** (로건, `screens.rs` 309줄) — `HORIZON_Y + 40.0 < GROUND_Y`의 40은 안개 아래끝(`draw_sea`의 `HORIZON_Y + 32.0`)과 이어져 있지 않아요. 안개를 `+ 60.0`으로 바꿔도 이 테스트는 그대로 통과해요(게다가 모래가 나중에 그려져 안개를 덮어요). 안개 아래끝을 상수(`HAZE_BELOW` 같은)로 빼서 테스트가 그 상수를 쓰게 하거나, 이 줄을 지워요. clippy도 "항상 같은 값" 경고를 내요.
7. **안개·빛기둥 안의 숫자** (로건, `sky.rs` 713~716줄, 749~764줄) — 34, 10, 32, 2.6, 0.45, 4.0 같은 그림 값이 함수 안에 있어요. 파일 맨 위에 "색·크기·빠르기는 이 파일 위쪽 상수에 모았다"고 써 있는데 이 부분은 아니에요. 게임 규칙은 아니라 급하지 않아요. 위쪽 상수로 옮기거나 맨 위 설명을 "대부분"으로 고쳐요.
8. **`SkyImages::get`과 `SkyArt::get`이 같은 `match`를 두 번 써요** (로건) — 그림 종류를 하나 더 하면 두 곳을 다 고쳐야 해요. 지금은 테스트용(`#[cfg(test)]`)이라 둬도 괜찮아요.
9. **매 프레임 작은 할당** (로건) — `draw_sky`의 `stops` Vec 1개 + `vgradient` 호출마다 Vec 2개 × 5번. 크기는 아주 작아서 지금은 괜찮아요. 신경 쓰인다면 하늘 `stops`를 `[(f32, Color); SKY_ROWS + 1]` 배열로 바꾸면 하나 줄어요.
10. **clippy 경고 2개** (로건, `sky.rs` 261·949줄) — `for k in 0..4 { img.bytes[i + k] = ... p[k] ... }`. `for (k, v) in p.iter().enumerate()`로 바꾸면 경고가 사라져요.
