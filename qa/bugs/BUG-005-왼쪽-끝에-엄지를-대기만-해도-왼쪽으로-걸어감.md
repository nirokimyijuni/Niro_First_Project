# BUG-005 화면 왼쪽 끝에 엄지를 대기만 해도 캐릭터가 왼쪽으로 걸어감
- 관련 스토리: US-032 ("엄지를 대고 가만히 있거나 살짝 떨려도 캐릭터가 흔들리지 않는다")
- 심각도: 중간. 가로로 든 폰에서 왼손 엄지는 화면 왼쪽 끝(양옆 띠 포함)에 놓이기 쉬워서 아이가 자주 겪을 수 있다. 손을 대자마자 캐릭터가 혼자 걸어가 "왜 가?" 하게 된다.
- 재현:
  1) 브라우저 모바일 크기 가로(740×360, 배율 2) 또는 844×390으로 열고 화면을 눌러 게임까지 간다 (아무 캐릭터)
  2) 캐릭터를 화면 가운데쯤에 둔다
  3) 화면 **왼쪽 끝**(왼쪽 띠 안, 또는 게임 화면 왼쪽 끝에서 손가락 하나 폭 안쪽)에 엄지를 대고 **움직이지 않는다**
- 기대: 조이스틱만 생기고 캐릭터는 가만히 있다. 밀어야 걷는다.
- 실제: 조이스틱 받침은 화면 안쪽으로 당겨져 생기고(REVIEW-003 3번 고침), 손잡이는 손가락이 있는 왼쪽 가장자리로 밀린 채 그려진다. 손잡이가 데드존 밖이라 캐릭터가 **바로 왼쪽으로 걷기 시작**하고, 엄지를 떼기 전까지 계속 걷는다.
  - 740×360: 손가락 (CSS 70, 200) = 가상 x 30 에 1초 가만히 → 캐릭터가 왼쪽 끝까지 걸어감 (스크린샷으로 확인)
  - 844×390: 손가락 (CSS 30, 380) = 왼쪽 띠 안 → 같은 증상
  - 계산: 받침 가운데 x는 최소 `JOYSTICK_RADIUS`(85)로 당겨지고, 데드존은 85×0.25 = 21. 그래서 가상 x가 약 **64보다 왼쪽**이면 대기만 해도 왼쪽으로 걷는다. 아이폰 12 Pro 가로처럼 양옆 띠가 75px 있는 폰은 띠 전체가 여기에 들어간다.
- 자동 테스트: `game/tests/m3_touch.rs`의 `bug005_resting_thumb_near_left_edge_does_not_walk` (지금은 `#[ignore]`, `cargo test --test m3_touch -- --ignored`로 돌리면 실패). 고치면 `#[ignore]`를 지운다.
- 참고(고치는 방법은 로건이 정함): 받침을 당길 때 "손잡이 기준점"도 손가락 자리로 두는 방법(받침은 그림만 안쪽에, 걷기 판정은 처음 댄 자리 기준) 등이 있다. 오른쪽 끝은 조이스틱 영역(왼쪽 절반)이 아니라 이 문제가 없고, 위·아래 끝은 세로 방향이라 걷기에 영향 없음.
- 고칠 사람: 로건
- 환경: 내장 브라우저(Chrome 152) 모바일 흉내 740×360 배율 2, 844×390 배율 1. 터치는 canvas에 TouchEvent를 직접 보내서 흉내 냄
- 고친 방법: (로건) 받침은 그림만 화면 안으로 당기고, 손잡이·걷기 판정은 처음 댄 자리(`Joystick::start`)를 중립으로 재서 밀어야만 걷게 했다 (view/touch.rs).
- 상태: 닫힘 (2026-11-06, 엘리 재확인)
- 재확인(2026-11-06, 엘리, 버전 3daa351-20261106104955): 740×360 배율 2, 844×390 배율 1에서 canvas에 TouchEvent로 확인. 왼쪽 끝(가상 x 30), 왼쪽 띠 안(CSS x 1·5·10·30), 왼쪽 아래, 가운데 쪽에 엄지를 0.8~0.9초 대기만 했을 때 캐릭터 이동 0, ±5px 떨어도 이동 0. 오른쪽으로 밀면 0.3초에 약 67 걸음. `bug005_...` 테스트는 `#[ignore]` 없이 통과. 남은 작은 문제는 BUG-007.
