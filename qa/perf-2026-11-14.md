# 성능 확인 2026-11-14 (엘리)

부모님 말: "중간중간에 끊기는 느낌이 들어." 배포판(933bfcf, https://nirokimyijuni.github.io/Niro_First_Project/)을 앱 브라우저로 열어 쟀다. 코드는 고치지 않았다.

## 잰 방법
- `requestAnimationFrame` 간격을 30~60초 기록하고, 평균 FPS, 가장 긴 프레임, 33ms·50ms를 넘은 프레임 수를 셌다.
- WebGL `texImage2D`·`texSubImage2D`를 감싸서 그림 올리기의 크기와 걸린 시간을 기록했다.
- 빨리감기는 켠 상태(기본값 x10). PC 브라우저의 devicePixelRatio는 1.25다.

정리: 게임 자체(몬스터, 그리기)는 60FPS가 나온다. 끊김은 **새 글자를 처음 그리는 순간**에 생기고, 오래 할수록(그리고 창 크기가 바뀔수록) 한 번 끊기는 시간이 길어진다.

## 원인 (가장 유력)
macroquad 0.4.16은 글꼴 글자를 큰 그림 한 장(아틀라스)에 모아 둔다.
- 새 (글자, 글꼴 크기)가 나오면 그 그림 **전체**를 GPU에 다시 올린다. 512면 1ms, 2048이면 10ms, 8192면 220ms가 걸린다.
- 그림이 꽉 차면 가로세로를 2배로 키우고 모든 글자를 다시 옮긴다. 이때 100~950ms 멈춘다. 지운 글자는 다시 빠지지 않는다.
- 8192×8192는 RGBA로 256MB다. wasm 메모리가 489MB가 된 이유다. 폰에서는 더 느리고, 메모리가 모자라 꺼질 수도 있다.

글자가 많이 생기는 이유 (파일:줄):
1. `game/src/view/text.rs:48` 글꼴 크기 = 글자 크기 × 화면 배율. 같은 글자도 크기마다 따로 그려 둔다. 크기 종류가 많고(24~76) 한글이라 글자 수도 많다.
2. `game/src/view/text.rs:43`, `game/src/main.rs:384` 화면 배율이 0.1만 바뀌어도 모든 글자를 새 크기로 다시 그린다. 창 크기 바꾸기, 폰 회전, 전체화면, 주소창 숨김이 모두 해당한다. 옛 크기 글자는 남아서 아틀라스를 키운다. 시험 A에서 8192까지 커진 것도 창 크기를 바꾼 뒤였다.
3. 진짜 폰(배율이 3)은 캔버스가 약 2436×1125라서 배율이 약 2.1이다. PC 시험(1.67)보다 글자 하나가 약 1.6배 넓다. 그래서 같은 놀이로도 아틀라스가 더 빨리 커진다. (진짜 폰은 직접 못 쟀다)
4. 퀴즈 문제, 말풍선, 쓰러짐 화면의 큰 글자(60~76)처럼 처음 보는 글자가 놀이 중간에 계속 나온다.
5. **출시 전 주의 (M8, 아직 커밋 안 됨):** `game/src/view/items.rs:99` "부릉!" 크기, `game/src/view/items.rs:186-187` "쿵!" pop 크기가 프레임마다 바뀐다. 매 프레임 새 글꼴 크기가 생겨 아틀라스가 아주 빨리 커진다. 이대로 나가면 차·쿵을 쓸 때마다 크게 끊길 가능성이 높다.

## 다른 후보 (덜 유력)
- `game/src/view/text.rs:26-33, 99-102` 글자 하나를 34번 그린다 (테두리 32 + 그림자 + 본문). PC에서는 60FPS가 나와 끊김 원인은 아니지만, 느린 폰에서는 CPU 부담이다.
- 몬스터·뼈·효과 목록은 쌓이지 않는 것으로 보인다. 좀비는 거리로 지우고(`logic/combat.rs:234`) 아침에 모두 지운다(`:203-204`). 효과도 지운다(`view/effects.rs:268`). 이벤트는 `take_*`로 비운다. 메모리가 늘어난 것은 아틀라스로 설명된다.
- 매 프레임 텍스처를 불러오지 않는다 (`Texture2D::from_image`는 `view/assets.rs`의 시작 때만 쓴다).

## 고칠 방향 (로건, `view/text.rs`·`view/items.rs`)
1. 글꼴 크기를 몇 단계(예: 실제 픽셀 24/32/48/64/96)로만 만들고, 나머지 크기는 `font_scale`로 늘리고 줄인다. 크기 종류가 줄어 아틀라스가 작게 유지된다.
2. 애니메이션 크기("부릉!", "쿵!")는 글꼴 크기를 고정하고 `font_scale`만 바꾼다. M8 출시 전에 고친다.
3. 화면 배율이 바뀌면 글꼴을 다시 불러와(`load_ttf_font_from_bytes`) 아틀라스를 512부터 새로 시작한다. 아니면 글꼴 배율에 상한(예: 2.0)을 둔다.
4. (선택) 불러오는 중 화면에서 자주 쓰는 글자(숫자, HUD, 퀴즈 글자)를 미리 한 번 그려 둔다.
수산나(로직) 쪽 일은 없다.

## 못 본 것
- 진짜 폰과 배율 3 화면은 직접 못 쟀다. 812×375 시험의 배율은 1.25였다.
- 쌓임을 보는 cargo 시험은 쓰지 않았다. 코드를 읽어 보니 목록은 지워지고, 메모리 증가는 아틀라스로 설명된다. 다른 사람이 고치는 중인 코드라 빌드도 하지 않았다.
- M8(아직 커밋 안 됨)은 브라우저에서 돌려 보지 않았다. 코드를 읽고 판단했다.
