# BUG-029 새 글자를 처음 그릴 때 게임이 잠깐씩 끊김 (글꼴 그림이 계속 커짐)
- 관련 스토리: - (여러 화면 공통, 글자 그리기 `view/text.rs`)
- 관련 리뷰: -
- 심각도: S3 (엘리 제안: 끊기지만 계속 놀 수 있다. 진짜 폰에서 메모리 때문에 꺼지면 S1으로 올린다)
- 발견 시점: 출시 후 (부모님 "중간중간에 끊기는 느낌")
- 영역: 화면
- 원인: (고친 뒤 적는다) 엘리 추정: 코드. macroquad 글꼴 아틀라스는 (글자, 글꼴 크기)마다 글자를 따로 쌓고, 새 글자가 나올 때마다 그림 전체를 GPU에 다시 올린다. `view/text.rs:48` 크기 × 배율로 글꼴 크기 종류가 많다. `view/text.rs:43`·`main.rs:384` 배율이 바뀌면 모든 글자를 새로 그리고, 옛 글자는 남는다. M8(아직 커밋 안 됨) `view/items.rs:99`, `:186-187`은 글자 크기가 매 프레임 바뀌어서 더 심해질 것이다.
- 재현: 1) 1280×720 창에서 게임을 연다 2) 창 크기를 한두 번 바꾼다 3) 낮→퀴즈→밤→쓰러짐 화면까지 논다
- 기대: 계속 60FPS로 매끄럽다 / 실제: 새 글자가 나올 때마다 100~950ms 멈춘다. 아틀라스가 8192×8192(256MB)까지 커지고 wasm 메모리가 53MB에서 489MB가 된다. 새 글자 하나를 올리는 데 220ms가 걸린다. 처음 연 뒤에도 79초에 2048로 커지면서 100ms 멈췄다.
- 환경: 앱 브라우저(Chrome 계열) PC 1280×720, devicePixelRatio 1.25, 배포판 933bfcf. 812×375 크기(배율 1.25)에서는 40초 동안 끊김이 없었다. 진짜 폰(배율 3)은 못 봤다.

## 엘리 다시 재기 (2026-11-14, dist 312ab00-20261114130853, 커밋 전 작업 트리)
- 고침 확인: `view/text.rs` 글꼴 크기 7단계(`FONT_PIXEL_STEPS`), `view/items.rs` "부릉!"·"쿵!"은 크기 고정 + 확대만 바꿈.
- 같은 방법(texImage2D·texSubImage2D 감싸기)으로 약 4분: 1280×720 → 740×360으로 창 크기를 바꾸고, 낮 → 상점 → 멈춤 창 → 퀴즈 → 밤 → 쓰러짐 화면까지.
  - 글꼴 그림: 처음부터 끝까지 **2048 그대로**, 4096·8192로 커지지 않음 (전: 8192)
  - wasm 메모리: **69MB** (전: 489MB)
  - 그림 올리기 66번, 대부분 6~25ms (2048 한 장 통째로). 쓰러짐 화면 처음 뜰 때 18번 몰림. 가장 긴 것 117ms·286ms 한 번씩.
- 못 본 것: 이번에는 앱 브라우저 창이 **숨겨진 상태**라 화면이 초당 2~3번만 그려졌다. 그래서 FPS·가장 긴 프레임은 전과 비교할 수 없고, 117·286ms도 숨김 탓인지 진짜 끊김인지 모른다. devicePixelRatio도 1이었다 (전 1.25). 진짜 폰은 못 봤다.
- 판단: 원인(아틀라스가 끝없이 커짐, 메모리)은 좋아졌다. 프레임 끊김은 보이는 창에서 한 번 더 재거나 부모님 폰 확인 뒤 닫는다. 그때까지 **열림, S3 → S4 제안**.
