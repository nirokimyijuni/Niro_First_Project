# REVIEW-031 로고·시작 화면 (US-109)

리뷰어: 밥 / 날짜: 2026-11-21 / 대상: 커밋 전 변경 (view/logo.rs, config.rs 끝, main.rs 로고 부분, assets.rs `load_font`, text.rs `plain_zoomed`, web/index.html, about.html, manifest)

## 이 변경이 하는 일
게임을 열면 Now Loading(도는 점) → "눌러서 시작" → 니로 스튜디오 로고(5.8초) → 타이틀 순서로 보여 준다. 칸 바뀜은 `Intro`라는 시계로 만들어 그리기와 떼어 놓았고, 폰에서는 키·펜 입력으로도 전체화면 + 가로로 바뀐다.

못 본 것: 실제 브라우저·폰에서 돌려 보기, cargo test·빌드(요청대로 안 돌림), og-image·아이콘 그림 자체, about.html 본문 문구 전체(헤드 부분과 ← → ↑ 만 확인).

## 잘한 점
- 칸 바꿈 규칙(`Intro::update`)이 그리기와 떨어져 있어서 시험이 쉽다. 한 프레임에 칸은 최대 한 칸만 넘어간다 (`next`가 한 번만 정해짐).
- 누름이 새지 않게 막은 방법이 분명하다: 칸을 바꾼 프레임의 누름은 다음 칸이 안 받고, 끝난 다음 프레임은 입력을 읽기 전에 `leave()`로 나간다. 손가락은 main과 같은 `TouchControls`를 써서 "대고 있는 손가락"이 새 누름이 되지 않는다. 이 세 가지 모두 시험이 있다.
- 시험의 반복문에는 전부 횟수 제한이 있다 (`while ... && frames < 600`, `for 0..1200`). 시간 값은 config.rs에 모여 있다.

## 확인한 것 (문제 없음)
1. 상태 꼬임: 한 프레임 dt는 `MAX_FRAME_SECONDS`(0.25)로 잘려 들어오고, 탭이 뒤에 갔다 와도 로고는 최대 0.25초만 간다. Loading은 `ready`(그림 다 받음)가 되면 반드시 나간다. `?qa`도 다 받은 같은 프레임에 Done이라 멈추지 않는다. 그림을 못 받는 경우는 아래 "고치면 좋은 것 3번".
2. 입력 새기: "눌러서 시작" 누름은 로고에 안 간다 (시험 `the_start_press_does_not_skip_the_logo`). 로고 넘긴 누름은 타이틀에 안 간다: 마우스·키는 macroquad가 프레임마다 비우고, 키 반복(꾹 누름)은 `repeat == false`일 때만 "눌림"이 되어서(macroquad 0.4.16 `key_down_event`) 계속 눌러도 새 누름이 아니다. 터치는 `finger_held_from_the_logo...` 시험이 확인한다.
4. 글자: 화면에 그리는 문자열은 "Now Loading...", "눌러서 시작", "Lucky Mis!", "NIRO STUDIO", "1""2""3""Hey"뿐이다. Jua에 없는 · — ↑ ←는 없다 (시험도 Now Loading의 글자를 확인). about.html의 ← → ↑는 HTML `<kbd>`라 게임 글꼴과 상관없다.
5. 수치: 시간·깜빡임 값은 config.rs "로고·시작 화면" 칸에 있고, logo.rs의 색·위치·크기는 그림 값이라 괜찮다. `HOP_HEIGHT`(뿅 높이)는 그림 값으로 보아 괜찮다.
6. 시험에 "될 때까지 반복"은 없다. 장면 루프(`play_logo`의 `loop`)는 횟수 제한이 없지만 화면 루프라 정상이고, 끝나는 길은 Intro 시험이 확인한다.

## 꼭 고칠 것
없음.

## 고치면 좋은 것
1. **전체화면: 키로 불리는 조건이 넓다** (로건, web/index.html 186~188줄). 폰·태블릿(`pointer: coarse`)에서 Esc 말고 모든 키가 `goFullscreen()`을 부른다. 예: 블루투스 키보드를 쓰는 태블릿에서 아이가 Esc로 전체화면을 나갔다가 다음에 아무 키(Shift, Ctrl+C, F12 포함)를 누르면 바로 다시 전체화면이 된다. 가장 작은 고침: `e.repeat`와 Shift/Ctrl/Alt/Meta 키는 건너뛰기 (`if (e.key !== "Escape" && !e.repeat && !e.ctrlKey && !e.metaKey && !e.altKey)`). 꼭은 아니다. 꾹 누르면 `fullscreenElement`가 생기기 전까지 요청이 여러 번 나가지만 `.catch`가 삼키니 해는 없다.
2. **노트북 터치스크린**: `pointer: coarse`는 "주 입력"이라 마우스가 달린 보통 노트북은 `fine`이라 PC 동작이 그대로다. 다만 태블릿 모드로 바뀌는 2-in-1 기기는 coarse가 될 수 있어, 그때 키를 누르면 전체화면이 된다 (위 1번과 같은 증상, 의도한 동작에 가깝다). `touchDevice`를 한 번만 재서 모드가 바뀌어도 안 따라간다. 질문: 이대로 괜찮은지 부모님께 확인하면 좋다. 스페이스 스크롤은 body가 `position: fixed; overflow: hidden`이라 일어나지 않고, 이 리스너는 `preventDefault`를 안 해서 게임 입력도 건드리지 않는다. 확인함.
3. **그림 받기에 실패하면 영영 "Now Loading..."** (수산나 아님, 로건, assets.rs). `load_with_font` 안의 `expect(...)`가 코루틴 안에서 터지면 `loading.retrieve()`는 계속 `None`이라 화면은 도는 점에서 멈춘다 (예: 그림 파일 하나가 배포에서 빠졌을 때). 전에는 시작 전에 터져서 빈 화면이었으니 나빠진 것은 아니지만, 아이에게는 "계속 기다리는" 모습이다. 가장 작은 고침: 엘리가 배포본에서 한 번 열어 보는 것으로 충분하고, 고치려면 `play_logo`에 "30초 넘게 못 받으면 '인터넷을 확인해 주세요' 한 줄" 정도. 이번 변경을 막을 이유는 아니다.

## 작은 것
- `logo.rs` `draw_loading`의 주석 "로고를 넘겼는데 그림을 아직 다 못 받았을 때"는 낡았다. 지금은 맨 처음 Loading 칸에서만 쓴다. 주석을 "그림을 받는 동안"으로 (로건).
- `Intro::skip`일 때 `Done` 프레임은 `logo().time() == 0`이라 빨간 화면 한 프레임만 그려진다 (`?qa` 전용, 해 없음).
- `play_logo`와 main 둘 다 `hide_loading_screen()`을 부른다. 두 번째는 이미 지워져 있어 아무 일도 안 한다 (JS가 `if (el)`로 막음). 그대로 둬도 된다.
- 로고가 시간으로 끝나는 바로 그 프레임에 사용자가 새로 누르면, 끝난 다음 프레임에서 main이 그 누름을 읽을 수 있다 (타이틀 버튼이 눌릴 수 있는 한 프레임짜리 아주 드문 경우). 지금 누름 방지는 "넘기는 누름"에 대해서만 완벽하다. 고칠 필요는 낮다.

## 시험이 바뀐 점
시험은 15개이고 새로 쓴 것이다. 약하게 만들어 통과시킨 흔적은 없다. 칸 순서, 누름이 안 새는 것, `?qa`, 손가락 이어짐, 화면 밖으로 안 나감이 각각 따로 있다. 빠진 시험: 로고 도중 누르면 바로 Done이 되는 것은 `Logo` 단위 시험이 있고 `Intro` 단위로는 `the_skipping_press...`가 확인한다. 충분하다.

## 아이 눈높이
"눌러서 시작", "Now Loading...", "Lucky Mis!", "NIRO STUDIO"는 쉽고 무섭지 않다. 개인정보 없음 (별명만).
