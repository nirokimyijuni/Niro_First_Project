# 게임 주소를 findmis.niro-studio.com으로 — 부모님 따라 하기 안내서

> 관리: 케빈(에이전트). 부모 결정 2026-11-21: 팀 도메인 `niro-studio.com`, 이 게임은 `findmis.niro-studio.com`. 다음 게임도 `○○.niro-studio.com`.
> **AWS 콘솔(웹 화면)만** 씁니다. 도메인 구매, 결제, 약관 동의, 인증서 요청, 스택 업데이트는 모두 부모님이 직접 합니다. 케빈은 AWS와 도메인에 아무것도 하지 않습니다.
> 먼저 [README.md](README.md)의 스택(`miss-game-hosting`)이 만들어져 있어야 합니다(이미 됨: 2026-11-21 첫 AWS 배포 성공).

## 시작 전에

- 루트 계정 말고 **관리자 사용자**로 로그인, **MFA** 켜져 있는지 확인 ([README.md](README.md) "시작 전에"와 같음).
- 1단계에서 도메인 연락처(이름·주소·전화·메일)를 넣습니다. 이 값은 **부모님이 콘솔에서만** 입력하고 어디에도 적지 않습니다. 케빈에게 알려 주지 않아도 됩니다.

## 1단계. Route 53에서 niro-studio.com 사기 (부모님 결제)

1. 위쪽 검색창 **Route 53** → 열기. (도메인은 리전과 상관없어요.)
2. 왼쪽 메뉴 **Domains** → **Registered domains**(등록된 도메인) → **Register domains**(도메인 등록).
3. 검색칸에 `niro-studio.com` 입력 → **Search**. "Available"(사용 가능)이면 **Select** → **Proceed to checkout**(결제로 진행).
   - "Unavailable"이면 이미 누가 가진 이름입니다. 여기서 멈추고 케빈에게 알려 주세요(다른 이름을 정해야 해요).
   - 이름 옆에 "Premium"이 붙어 있으면 값이 비쌉니다. 사지 말고 알려 주세요.
4. **Pricing**(가격) 화면:
   - **Duration**(기간): `1 year`.
   - **Auto-renew**(자동 갱신): **켜기**. 끄면 1년 뒤 주소가 끊기고 남이 가져갈 수 있어요.
   - 여기 나오는 **1년 가격을 확인**하고 → **Next**.
5. **Contact information**(연락처): 부모님 정보를 직접 입력. 연락처 메일은 부모님이 자주 보는 메일로.
   - **Privacy protection**(개인정보 보호): **켜기**(보통 기본으로 켜져 있음). 켜면 도메인 공개 조회(WHOIS)에 이름·주소·전화가 안 나와요.
   - → **Next**.
6. **Review**(검토): 도메인 이름 `niro-studio.com`, 자동 갱신 켜짐, 개인정보 보호 켜짐, 금액 확인 → 약관(Terms) 체크 → **Submit**(제출). 결제는 AWS 계정에 등록된 카드로 나갑니다.
7. **호스팅 존은 자동으로 만들어집니다.** 따로 만들지 마세요(두 개가 되면 헷갈리고 돈도 두 배).
8. 왼쪽 **Requests**(요청)에서 상태를 봅니다. 보통 몇 분~몇 시간 뒤 **Successful**(성공). 그 뒤 **Registered domains** 목록에 `niro-studio.com`이 보입니다.

## 2단계. 연락처 메일 확인 (꼭!)

- 연락처 메일로 "verify your email"(메일 확인) 메일이 옵니다(처음 쓰는 메일일 때). **링크를 눌러 주세요.** 15일 안에 안 누르면 도메인이 멈춥니다(ICANN 규칙).
- 메일이 안 오면 **Registered domains** → `niro-studio.com` → 연락처 메일 옆 **Resend**(다시 보내기).

## 3단계. 호스팅 존 ID 복사

1. Route 53 왼쪽 **Hosted zones**(호스팅 영역) → `niro-studio.com` 클릭.
2. **Hosted zone details**(호스팅 영역 세부 정보)를 펼치면 **Hosted zone ID**가 있어요. `Z`로 시작하는 글자(예: `Z0123456789ABCDEFGHIJ`). 복사해 둡니다. 비밀번호가 아니에요.
3. 안에 이미 있는 `NS`, `SOA` 레코드 두 줄은 **지우지 마세요.** 지우면 주소가 안 열립니다.

## 4단계. ACM 인증서 요청 — 꼭 버지니아(us-east-1)에서

CloudFront는 **미국 동부(버지니아 북부) us-east-1** 리전의 인증서만 받습니다. 서울에서 만들면 5단계에서 쓸 수 없어요(템플릿이 막습니다).

1. 오른쪽 위 리전을 **US East (N. Virginia) us-east-1**로 바꿉니다.
2. 검색창 **Certificate Manager** → 열기 → **Request**(요청) (또는 **Request a certificate**).
3. **Request a public certificate**(퍼블릭 인증서 요청) → **Next**.
4. **Fully qualified domain name**(정규화된 도메인 이름): `findmis.niro-studio.com`
   - (선택, 아래 "와일드카드를 넣을까?" 참고) **Add another name to this certificate**(이 인증서에 다른 이름 추가) → `*.niro-studio.com`
5. **Validation method**(검증 방법): **DNS validation - recommended**(DNS 검증 - 권장).
6. **Key algorithm**(키 알고리즘): 기본값 **RSA 2048** 그대로 → **Request**(요청).
7. 인증서 목록에서 방금 만든 것(상태 **Pending validation**, 검증 대기) 클릭.
8. **Domains**(도메인) 칸 오른쪽 위 **Create records in Route 53**(Route 53에서 레코드 생성) → 이름이 체크돼 있는지 보고 → **Create records**(레코드 생성).
   - 와일드카드를 함께 넣으면 검증 CNAME이 두 줄 생기고, 둘 다 있어야 Issued가 됩니다. 두 이름 모두 체크된 채로 **Create records**를 누르세요.
9. 몇 분~30분 기다리면 상태가 **Issued**(발급됨, 초록색). 새로고침해 가며 봅니다.
10. 인증서 세부 정보 맨 위 **ARN**(`arn:aws:acm:us-east-1:...:certificate/...`)을 복사해 둡니다. 비밀번호가 아니에요.
11. Route 53에 새로 생긴 `_`로 시작하는 검증 줄(`CNAME`)은 **모두 지우지 마세요.** 지우면 13개월 뒤 자동 갱신이 실패합니다(ACM이 알아서 갱신, 무료).

### 와일드카드(`*.niro-studio.com`)를 같이 넣을까?

| | `findmis.niro-studio.com`만 | `*.niro-studio.com`도 같이 |
|---|---|---|
| 다음 게임 | 게임마다 인증서를 새로 요청(이 4단계를 다시, 5분) | 이 인증서 하나로 `○○.niro-studio.com` 모두 됨. 새 게임은 인증서 단계 생략 |
| 공개되는 정보 | 인증서 이름은 공개 기록(인증서 투명성 로그)에 남아, 게임 이름이 공개 전에 드러날 수 있음 | 이름이 `*`라서 앞으로 만들 게임 이름이 미리 드러나지 않음 |
| 문제가 생기면 | 이 게임만 영향 | 이 인증서를 지우거나 바꾸면 그걸 쓰는 모든 게임이 같이 영향(CloudFront에 붙어 있으면 지우기가 막히긴 함) |
| 범위 | — | 한 단계만: `a.niro-studio.com`은 되고 `niro-studio.com`(맨 앞 없는 주소)이나 `a.b.niro-studio.com`은 안 됨 |
| 값 | 무료 | 무료 |

**케빈 추천: 같이 넣기.** 앞으로 다른 게임도 `○○.niro-studio.com`으로 정해 두셨고, 비용 차이가 없고, 단계가 줄어요. 맨 앞 주소 `niro-studio.com`을 나중에 팀 소개 페이지로 쓰려면 그때 그 이름만 따로 인증서를 요청하면 됩니다. 정하는 건 부모님입니다.

## 5단계. CloudFront에 도메인 붙이기 — 스택 업데이트 (서울)

템플릿([game-hosting.yaml](game-hosting.yaml))에 칸 3개가 새로 생겼습니다. 셋 다 비우면 지금과 똑같이 `cloudfront.net`만, 넣으면 CloudFront에 대체 도메인(Alternate domain name)과 인증서가 붙고 Route 53에 `findmis` 별칭 레코드(A·AAAA → CloudFront)까지 만들어집니다. **콘솔에서 레코드를 따로 만들 필요가 없어요.**

| 새 칸 | 넣을 값 |
|---|---|
| `DomainName` | `findmis.niro-studio.com` |
| `AcmCertificateArn` | 4단계에서 복사한 ARN (`arn:aws:acm:us-east-1:` 로 시작) |
| `HostedZoneId` | 3단계에서 복사한 ID (`Z`로 시작) |

1. 새 `game-hosting.yaml`을 컴퓨터에 받아 둡니다. (아직 커밋 전이면 이 PC의 `D:\...\미쓰 찾기 게임\deploy\aws\game-hosting.yaml`.) **밥(리뷰어)의 리뷰가 끝난 파일인지 케빈에게 확인**하고 쓰세요.
2. 오른쪽 위 리전을 다시 **Asia Pacific (Seoul) ap-northeast-2**로 바꿉니다.
3. **CloudFormation** → `miss-game-hosting` 선택 → **Update**(업데이트) → (메뉴가 나오면 **Make a direct update**).
4. **Replace existing template**(현재 템플릿 교체) → **Upload a template file** → 새 `game-hosting.yaml` → **Next**.
5. **Parameters**: 기존 칸은 그대로 두고, 위 표의 3칸만 채웁니다 → **Next**.
   - 값을 하나만 넣거나 버지니아가 아닌 인증서 ARN을 넣으면 이 화면에서 바로 빨간 글씨로 막힙니다. 글씨대로 고치면 돼요.
6. **Configure stack options**: 그대로, 맨 아래 **"I acknowledge that AWS CloudFormation might create IAM resources."** 체크 → **Next**.
7. **Review** 화면 아래 **Changes**(변경 세트 미리보기)에서 세 가지를 확인합니다. 하나라도 다르면 **Submit하지 말고 멈추고** 케빈에게 알려 주세요.
   - [ ] `SiteDistribution`: **Modify**(수정)
   - [ ] `DomainRecordA`, `DomainRecordAAAA` 두 개: **Add**(추가)
   - [ ] 어느 줄에도 **Replacement: True**(교체)가 없음
8. **Submit** → **UPDATE_COMPLETE**(초록색)까지 5~15분.
   - **UPDATE_ROLLBACK_COMPLETE**면 예전 상태로 돌아간 것(게임은 `cloudfront.net` 주소로 계속 열림). **Events** 탭 빨간 줄 **Status reason**을 케빈에게 알려 주세요. 흔한 원인: 인증서가 아직 Issued가 아님, 인증서 이름에 findmis가 없음.
9. **Outputs** 탭에 새 줄 **PublicDomain** = `findmis.niro-studio.com`이 보입니다.

> 다른 길(쉽지 않아서 비추천): `HostedZoneId`를 비우고 스택 업데이트 → Route 53 → 호스팅 존 `niro-studio.com` → **Create record** → 이름 `findmis`, 유형 `A`, **Alias** 켜기 → **Alias to CloudFront distribution** → 목록에서 배포 고르기 → **Create records**. 같은 걸 유형 `AAAA`로 한 번 더. 이 경우 스택을 지울 때 레코드는 남으니 손으로 지워야 해요. 템플릿 길은 스택이 레코드도 같이 관리합니다.
> 손으로 만든 뒤 나중에 `HostedZoneId`를 넣어 템플릿 길로 바꿀 거라면, **그 전에 손으로 만든 `findmis` A·AAAA 두 줄을 먼저 지우세요.** 남아 있으면 같은 이름이 이미 있어서 스택 업데이트가 실패합니다.

## 6단계. GitHub 변수 하나 더

1. GitHub 저장소 → **Settings** → **Secrets and variables** → **Actions** → **Variables** 탭 → **New repository variable**.
2. **Name** `AWS_PUBLIC_DOMAIN`, **Value** `findmis.niro-studio.com` (앞에 `https://`, 뒤에 `/` 없이) → **Add variable**.
3. 이 변수가 있으면 배포 때 `cloudfront.net` 주소와 **새 주소 둘 다** 버전과 `.wasm` 종류를 자동 확인합니다(하나라도 틀리면 배포 실패로 표시). 이 확인 단계는 케빈이 고친 `deploy.yml`이 main에 올라간 뒤부터 동작합니다. 그 전에는 변수가 있어도 무시돼요.

## 7단계. 확인

1. 브라우저에서 **https://findmis.niro-studio.com** 을 엽니다. 주소창에 자물쇠가 있고 게임이 뜨면 성공.
   - 바로 안 열리면 10~30분 뒤 다시. 새 주소가 인터넷에 퍼지는 시간이에요. 휴대폰은 와이파이를 껐다 켜 보세요.
   - "안전하지 않음"(인증서 오류)이 뜨면 4단계 인증서 이름에 `findmis.niro-studio.com`(또는 `*.niro-studio.com`)이 있는지 확인.
2. 버전 확인: F12 → **Console**의 `게임 버전: ...` 줄, 또는 페이지 소스(Ctrl+U)에서 `window.GAME_VERSION`이 GitHub Pages·`cloudfront.net` 주소의 것과 같은지.
3. 예전 주소들(`https://nirokimyijuni.github.io/Niro_First_Project/`, `https://<...>.cloudfront.net/`)도 **계속 열립니다.** 정상이에요.
4. **새 주소를 다른 사람에게 알리는 건 부모님이 정할 일**입니다. 케빈은 묻지 않고 공유하지 않아요.

## 8단계. 대표 주소 바꾸기 — 도메인이 열리면 이 한 줄 (케빈)

7단계에서 새 주소가 열린 걸 부모님이 확인해 주시면, 케빈이 **이 한 줄만** 바꿉니다.

```
deploy/seo/site-url.txt
- https://nirokimyijuni.github.io/Niro_First_Project/
+ https://findmis.niro-studio.com/
```

그러면 빌드(`deploy/build.sh`)가 아래를 모두 새 주소로 채웁니다. web/ 파일은 손대지 않아요.
- `index.html`, `about.html`의 `canonical`, `og:url`, `og:image`, `twitter:image`
- `sitemap.xml`의 주소들, `robots.txt`의 `Sitemap:` 줄

**GitHub Pages 주소는 그대로 열리고**, 그 페이지의 canonical이 새 주소를 가리키게 되어 구글은 `findmis.niro-studio.com`을 대표로 고릅니다. 새 주소에서는 `robots.txt`가 도메인 맨 위(`/robots.txt`)에 놓여 로봇이 실제로 읽어요(github.io 하위 경로의 한계가 없어짐).

배포는 출시 기준(이번 릴리스 스토리 엘리 통과, 열린 S1·S2 버그 0개, `cargo test`·wasm 빌드 통과)을 확인한 뒤 다음 커밋에 함께 올립니다. 배포 뒤 공개 주소에서 `canonical`, `sitemap.xml`, `robots.txt`를 직접 확인합니다.

### 구글 검색(Search Console)은 새 주소로 다시 (부모님)

- 대표 주소가 바뀌면 Search Console에 **새 속성**을 추가합니다. 이제 내 도메인이라 **"도메인" 방식**을 쓸 수 있어요: 속성 추가 → **도메인** → `niro-studio.com` → 구글이 주는 `TXT` 값을 Route 53 호스팅 존에 **Create record**(유형 `TXT`, 이름 비움)로 넣고 → 확인. 한 번 해 두면 `○○.niro-studio.com` 모든 게임이 같이 확인됩니다.
- 그다음 **Sitemaps**에 `https://findmis.niro-studio.com/sitemap.xml` 제출.
- 예전 github.io 속성은 지우지 않아도 됩니다.

## 되돌리기

- **도메인만 떼기**: 5단계처럼 스택 업데이트에서 `DomainName`, `AcmCertificateArn`, `HostedZoneId` 세 칸을 **모두 비우기**. CloudFront는 `cloudfront.net`만, `findmis` 레코드는 스택이 지웁니다. 그 전에 케빈이 `site-url.txt`를 예전 주소로 되돌려 배포하고, GitHub 변수 `AWS_PUBLIC_DOMAIN`을 지웁니다.
- **도메인 자체를 그만 쓰기**: Route 53 → Registered domains → `niro-studio.com` → **Auto-renew 끄기**. 남은 기간까지는 유지되고 환불은 없어요. 다 끝난 뒤 호스팅 존(NS·SOA만 남긴 상태)을 지우면 월 $0.50도 멈춥니다.
- 인증서는 CloudFront에서 떼어 낸 뒤에만 지울 수 있어요(무료라 남겨 둬도 됩니다).
